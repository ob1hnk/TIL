# 카테고리 정의

`### [카테고리] 제목`의 대괄호 안에는 아래 7개 코드만 쓴다. 닫힌 목록이다.
애매하면 `ETC`에 넣고, `ETC`가 쌓이면 그때 새 코드를 추가할지 판단한다.

| 코드 | 범위 | 판단 기준 |
|---|---|---|
| `ML` | 머신러닝·딥러닝 이론, 알고리즘, 평가지표 | "왜 이렇게 되는가"가 주제일 때 |
| `STAT` | 확률, 분포, 추정, 가설검정, 실험설계, 통계적 회귀분석 | 모델이 아니라 데이터 자체를 다룰 때 |
| `PYTHON` | 파이썬 문법, 라이브러리 API (pandas, numpy, sklearn, keras) | "이 함수를 이렇게 쓴다"가 주제일 때 |
| `SQL` | 쿼리 문법, 조인, 윈도우 함수, 스키마, 쿼리 최적화 | 데이터베이스에 직접 던지는 것 |
| `DSA` | 코딩테스트 문제 풀이, 자료구조, 알고리즘 패턴 | 문제 하나를 푼 기록 |
| `INFRA` | git, Docker, VS Code, 가상환경, 배포, 클라우드 | 코드 밖의 개발 환경 |
| `ETC` | 나머지 | 위 어디에도 안 붙을 때 |

경계가 겹칠 때:

- 라이브러리로 배웠어도 이론이 핵심이면 → `ML` (예: "sklearn으로 본 편향-분산 트레이드오프")
- 이론 맥락이어도 API 사용법이 핵심이면 → `PYTHON` (예: "sklearn Pipeline에 ColumnTransformer 끼우기")
- pandas로 하는 집계·전처리 → `PYTHON`, DB에 던지는 쿼리 → `SQL`
- 코테 문제를 풀다 알게 된 파이썬 문법 자체가 수확이면 → `PYTHON`
  (`heapq` 사용법은 `PYTHON`, "이 문제는 힙으로 푼다"는 `DSA`)
- 통계 개념이어도 모델의 학습·성능이 주제면 → `ML`, 데이터의 분포·추론이 주제면 → `STAT`
  (분류기의 정밀도·재현율은 `ML`, p-value와 유의수준은 `STAT`)
- 프로젝트(EPICURE 등)에서 얻은 것은 일반화되는 주제 코드에 넣고, 그 프로젝트 안에서만
  의미가 있으면 `ETC`

`DSA` 항목은 제목을 `문제명 (Lv.N, 정답률 NN%)`으로 통일한다. 프로그래머스는 문제 번호를
화면에 드러내지 않으므로 레벨(`Lv.0`~`Lv.5`)과 정답률을 대신 적는다. 정답률은 푼 시점의
값이라 나중에 달라질 수 있지만, 체감 난이도를 되짚는 용도라 갱신하지 않는다.

`DSA`의 태그 줄은 **자료구조 + 유형** 순서로 붙인다 (`#heap #greedy`). 특정 자료구조를
쓰지 않은 문제면 자료구조 자리를 비우고 유형만 쓴다. 이렇게 두면 나중에 `--tag heap`으로
"힙으로 푼 문제"를 한 번에 뽑을 수 있다.
